# Production audit — 2026-09-24

Base: `main` at `8845fb3ec27d4335b14d9aeeaa209fe8f1d1398b`.
Scope: frontend, FastAPI backend, SQLite/PostgreSQL adapter, Vercel rewrites and
headers, Render Blueprints and Supabase connection/storage design. Changes are
proposed in a separate PR; production settings and `main` were not changed.

## Findings and corrections

| Area | Finding | Correction |
|---|---|---|
| Reports / remote DB | Annual progress repeatedly opened database connections for each day's logs/goals/weights. Thousands of network connections could make the page unusable. | One account-scoped request snapshot for summary, reports and progress. Regression checks 365 days with at most two connections including authentication, freshness and user isolation. |
| Authentication / DB | Synchronous session queries ran on the ASGI event loop, blocking other requests while PostgreSQL connected/responded. | Run session lookup in a worker thread; regression verifies the query runs off the event loop. |
| API security | Auth middleware could return before security headers; API responses had no explicit private/no-store policy. | Outermost header middleware protects auth failures and marks API responses private/no-store. |
| Data validation | Extremely large finite nutrition input and tiny recipe portion denominators could overflow calculated values and produce server errors. | Bound numerical inputs, require meaningful positive portions and validate generated food records before saving. |
| Vercel security | Live frontend responses lacked the CSP already used by the backend-served frontend. | Add that policy to Vercel response headers. |
| Vercel configuration | A stale REACT_APP_BACKEND_URL could silently bypass the same-origin proxy and break session cookies. | Reject this configuration at build time on Vercel with an actionable error. |
| Render cold start | Frontend requests timed out at 30 seconds while the free service can take over 50 seconds to wake. | Increase API timeout to 90 seconds, without automatic HTTP write retries. This does not guarantee every cold start completes. |
| Local development | Vite's same-origin API calls had no backend proxy. | Proxy /api to localhost:8000; verified through the running dev server. |
| Account form | Username pattern used an unescaped hyphen, invalid in modern HTML pattern v-mode. | Escape the literal hyphen. |
| Native bridges | Timeout or synchronous bridge failure retained event listeners. | Clean listeners/timers on failure in Health and notifications; notification regressions cover both paths. |
| Optional SQLite hosting | Paid disk Blueprint set maxShutdownDelaySeconds, which Render rejects for disk services. | Remove the incompatible field. Default free PostgreSQL Blueprint remains unchanged. |
| Instructions | Old hosting instructions implied Vercel required a paid disk and named an obsolete branch/timeout. | Align documentation with main, free PostgreSQL hosting and current behavior. |

## Coverage and boundaries

Existing automated suites cover accounts/recovery, access isolation, CRUD for
food/water/training/weight, goals, reports, saved meals, recipes, programs,
completed sets, measurements, profile/photo validation, backups/imports,
idempotent offline replay, barcode lookup mocks, reminders and PWA caching.
Code/config review also covered private PostgreSQL schema setup, secure cookies,
CSRF/origin checks, VAPID persistence, and same-origin reverse proxy routing.
No destructive migration or production restart was performed.

This is not an assertion that every provider setting or physical device works:

- No authenticated access to Vercel/Render/Supabase dashboards: actual grants,
  exposed schemas, quotas, provider backup availability and secret values
  cannot be independently inspected. Keep the fittrack schema private and
  DATABASE_URL only in Render. Do not post credentials in the PR or chat.
- Real camera/gallery permission flows, physical barcode capture, push delivery
  with a closed app, and signed native Apple Health require device testing.
  Safari/PWA cannot directly access HealthKit. No iOS signing or build was done.
- USDA requires an optional private API key; external food database availability
  and completeness are not guaranteed by mocked integration tests.
- Free Render sleeps: scheduled server reminders can be missed while asleep.
  Increasing the frontend timeout does not make the worker run while sleeping.
- Supabase quota/pausing and full-database backups remain hosting operations.
  Personal JSON exports do not back up every account, sessions or passwords.
